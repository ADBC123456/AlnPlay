# AlnPlay 媒体库与弹幕修复方案

## 目标与交付

修复详情页卡顿、剧集索引更新不及时、弹幕绑定失效及空结果无法刷新问题，保留服务器配置、媒体库、观看记录和用户手动匹配。

## 媒体库与性能

1. 应用启动及回到前台对已收藏目录调用现有 `refreshStale`，沿用 30 分钟有效期；先显示缓存，再后台扫描。服务层合并重复任务，自动失败冷却 5 分钟，手动刷新不受冷却限制，扫描成功才更新成功时间。
2. `LibrarySnapshot` 使用按实例缓存的查询索引，预先建立标题到文件、剧集到版本、标题到可用集数映射；同一快照重复查询直接查表，每个候选文件名最多解析一次。
3. 精确绑定优先。仅对同标题、非 missing、未手动绑定、且 episodeId 为空或失效的文件，用明确的 `SxxEyy` 补齐关联；有效绑定不得被文件名匹配改写。观看历史解析同样兼容失效 episodeId。
4. 分离目录发现与元数据识别：目录发现和文件落库不等待 TMDB 批次完成；使用最多 32 个待处理任务及最多 2 个网络请求并发；搜索、详情和整季结果在单轮扫描内复用成功缓存，失败不长期缓存。先写文件/季集关联，再补剧名、剧照、简介，元数据失败保留已有信息。
5. 扫描进度通知最多每 250ms 一次；详情页仅在快照变化时重算剧集查询，进度变化只更新状态。保留取消、代次校验及部分扫描不标旧文件 missing 的约束。
6. 区分扫描中、更新失败和完整扫描后的不可用状态；详情页刷新从该标题全部历史文件取得根目录，包含 missing 文件。

## 弹幕绑定与加载

1. 增加共享身份键转换函数，规范为 `danmaku:<resumeKey>`；播放器、批量匹配、预缓存和徽标查询统一使用，读取兼容旧键。新旧记录并存时优先手动绑定，再选更新时间较新的记录，首次写入串行迁移去重且不清空用户绑定。
2. `forceRefresh` 从播放器贯通到绑定加载、自动匹配、元数据匹配和仓储层；刷新保留用户选定远程剧集但跳过其缓存重新下载。同一缓存键串行写入并校验请求代次。
3. 非空缓存保持长期复用；有效空结果只缓存 5 分钟，过期自动重取。统一按 `fetchedAtMs` 判断，手动刷新立即重取，网络失败不覆盖已有有效内容。
4. 区分接口错误、解析失败和真正零条；解析失败不缓存为零条，只有合法空数组才算空结果。
5. 按启用来源优先级尝试绑定；空或失败继续尝试其他已绑定来源。用户绑定不自动替换。汇总优先级为有内容、加载失败、全部有效为空，并保留各来源原因。
6. 视频准备与弹幕请求并行，弹幕抵达后按当前播放时间同步；关闭、换集和重载用取消令牌与代次校验阻止旧内容写回新会话。

## 测试与验收

覆盖索引、扫描、弹幕端到端、设备回归、性能和 Android/iOS 构建验证。日志不记录凭据、完整认证 URL 或弹幕正文。
